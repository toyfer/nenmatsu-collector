公式仕様・他ソフト実装との対照

自作ツールが準拠すべき公式仕様と、他のソフトがどう実装しているかの整理
← トップへ戻る
自ツールは現在、独自34列CSVが基準です給与システム側がそのCSVを読む機能を持たない限り、手作業が残ります。公式ルートは国税庁の「申告書XML定義書」に則ったXMLです。

1. 公式仕様（実質的な標準実装）

国税庁の年調ソフトはXMLを出力します。定義書は国税庁の仕様公開ページで更新されます。

  • 年末調整申告書XMLデータに係る仕様公開・FAQ：控除申告書データを給与システム等にインポートする仕組みの説明
  • 控除申告書データに係る仕様公開：申告書XML定義書【正式版】・変更履歴付の公開場所
  • 年末調整手続の電子化に向けた取組について：XML定義書や年調ソフトの公開状況の更新履歴
  • 源泉徴収票等のオンライン送信に係る仕様書一覧：法定調書の電子送信仕様
  • 給与支払報告書の提出：令和8年分以後は「総務省通知形式CSV」、令和7年分以前は「統一CSVレイアウト」

国税庁のFAQには「年調ソフト以外のソフトウェアで作成した控除申告書データが、公開しているXML定義書に則ったデータである場合は、インポートすることが可能です」とあります。自作ツールが公式ルートに乗る条件は、この一文です。

3. 共通している設計（5層）

多くの製品は次の5層で実装しています。

  1. 従業員が入力する画面（Web・アプリ）
  2. 控除証明書等の電子データ取込（マイナポータル連携、QRコード付証明書）
  3. 控除額の検算と改ざん検知
  4. 給与システムへのインポート（年調ソフトXML形式）
  5. 法定調書・給与支払報告書の作成（e-Tax・eLTAX）

自ツールは1から3を作り、4を独自34列CSVで代替しています。ここが唯一の分岐点です。

4. 自ツールとの差分と今後の選択肢

  • 独自CSVのまま進める場合：給与システム側に読み込み機能が必要で、手作業が残ります。
  • XML定義書に準拠させる場合：staff.html の XML_MAP に定義書の要素名を書き写し、verified を true にして、実際にインポートできることを確認します。
  • 令和8年分は年調ソフトの正式版が10月公開予定で、定義書も更新されます。突合は確定版を待つのが安全です。
  • 給与支払報告書は令和8年分からCSVレイアウトが変わります。自ツールのCSVと、その先の提出データは別系統であることを明示してください。

5. 未確認事項

  • 申告書XML定義書【正式版】の要素名の全文。公開ページから取得して突合する必要があります。
  • 給与システム側が年調ソフトXMLの取込に対応しているか。ベンダーへの確認が最短です。
  • 日本語の年末調整OSSは実質存在しないため、実装の参考は公開仕様とベンダーの対応表になります。
