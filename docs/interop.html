1. 結論：実装を決めているのは各社のコードではなく公式仕様

年末調整の申告データを給与システムへ渡す形式は、各社が独自に決めているのではなく、国税庁が公開する「申告書XML定義書」が事実上の共通仕様になっています。年調ソフトの出力はXMLで、その定義書が公開されています。

国税庁の「年末調整控除申告書作成用ソフトウェアに関するFAQ」は、次のように答えています。

年調ソフト以外のソフトウェアで作成した控除申告書データが、公開しているXML定義書に則ったデータである場合は、インポートすることが可能です

つまり、自作ツールが公式ルートに乗る条件は「XML定義書に則っていること」です。このリポジトリのXML出力は、この条件を満たしているかどうかを XML_MAP.verified で管理しています。

3. ベンダーの実装（公開情報の範囲）

製品申告データの受取・連携
PCA給与シリーズ「年末調整データの受入」機能で、年調ソフトと同一のXML形式を取り込みます。他社サービスが同形式で作成したデータの取込条件も公開しています。
給与大臣NX令和8年版年調ソフトが出力する申告書データのインポートに対応しています。e-Tax・eLTAXの令和9年1月以降の電子申告にも対応しています。
forrou（cells）年調ソフト形式のデータ取込機能を実装済みです。令和8年分については「関係行政機関からの仕様公開後に開発」と明記しています。
SmartHR自社で集めた申告データを、ActRecipeの「年調ソフトXML形式 年末調整連携」でXMLに変換し、年調ソフトや対応する給与システムへ渡します。SmartHRの項目とXMLの対応表も公開しています。
freee人事労務給与計算から年末調整計算までを自社で完結させ、結果をfreee申告へ連携します。SmartHRからの申告情報の取込にも対応しています。
弥生給与eLTAX提出用CSVの項目一覧を公開し、PCdeskに取り込む運用です。
年調・法定調書の達人／達人Cube帳票イメージで入力し、給与ソフトと連動します。

各製品の内部実装は非公開です。確認できるのは、公開された取込機能・対応表・マニュアルの範囲です。

4. 共通している設計（5層）

  1. 従業員が入力する画面（Webフォームまたはアプリ）
  2. 控除証明書等の電子データ取込（マイナポータル連携、QRコード付証明書）
  3. 控除額の検算と、控除証明書データの改ざん検知
  4. 給与システムへのインポート（年調ソフトXML形式、または各社の独自CSV）
  5. 法定調書・給与支払報告書の作成（e-Tax／eLTAX）

このツールは1〜3を作り、4を独自CSVとXML（突合後）で担います。5は行いません。

5. 確認できないこと

  • 各社のソースコードと内部実装。公開された対応表・マニュアル以上は分かりません。
  • 申告書XML定義書の要素名そのもの。定義書は国税庁のページから取得し、このリポジトリの XML_MAP に写してください。
  • 給与システムが年調ソフトXMLの取込に対応しているか。これは各ベンダーへの確認が最短です。

6. 参考：オープンソースの状況

日本語の年末調整・給与計算のオープンソースは、探した範囲では実質存在しません。参考になるのは海外実装で、たとえばドイツの marcellehmann/lohnsteuer は、連邦財務省が公開する計算手順（Programmablaufplan）からコードを自動生成する設計です。日本にも財務省告示「電子計算機等を使用して源泉徴収税額を計算する方法」や国税庁の年末調整計算シートという対応物がありますが、OSS化した例は見当たりませんでした。
