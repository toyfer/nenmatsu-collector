信頼性の担保と検証手順

自作ツールで年末調整データを集める場合に、何をどう担保し、どう検証するか
← トップへ戻る
このツールは控除額・税額を計算しません 金額は事実（払込額・見積額）として集めるだけです。控除額の判定と税額の計算は給与システム側で行ってください。

1. 信頼性は1つの性質ではない

「信頼できるのか」と一括で問うと議論が終わりません。少なくとも次の5つの軸に分けてから潰します。

軸何が問われるか担保の方法
正確性値が正しく、必要な項目が漏れていないか入力時の必須・形式・矛盾チェック、人事側の再検証、前年差分レビュー、回帰テスト
真正性本人が申告した内容であり、後から書き換えられていないか確認書への自署押印、提出日時・職員番号・ツール版の記録、保存場所のアクセス権
監査可能性後から経緯を説明できるか提出記録の保存、要確認リストの履歴、変更履歴、確認書原本の保管
可用性担当が変わっても回るか、年度更新に追随できるか手順書、テスト記録、担当の複数化
機密性個人情報が漏れないかサーバーを持たない構成、保存場所と期間の明示、共有フォルダのアクセス権による統制

2. 最も重要な設計判断：ツールの位置づけを下げる

このツールを「法定申告書を作るツール」と定義しないでください。「人事が内容を確定するための、一次データ収集・検証ツール」と定義します。この定義にすると、要求される信頼性の水準が現実的になります。

法定申告書そのものの真正性は、従来どおり次のいずれかで担保します。

  1. 書面で確定する。ツールが出力する確認書に自署押印し、それを内容確認票として保管する。
  2. 公式ソフトに転記して確定する。国税庁の年調ソフトに転記し、公式の控除申告書データとして提出する。
  3. 給与システムの取込機能で確定する。給与システムがCSV取込を公式にサポートしている場合、それを原本とする。

国税庁は「従業員から提供を受ける年末調整申告書データや控除証明書等データを、ご利用の給与システム等にインポートし、年税額等の計算を行うためのシステムの改修等を行います」と整理しています。つまり「従業員がデータを作り、給与システムに取り込む」という流れ自体は公式の想定と同じ方向です。違うのは、そのデータを作るのが公式ソフトか自作ツールか、という点だけです。

3. チェックサムの限界

このツールは、提出CSVにチェックサム（SHA-256、利用できない環境ではFNV1a-32）を付与し、人事側の取り込み時に自動照合します。

これは事故と改変の「検知」には有効ですが、悪意ある改ざんに対する真正性の担保にはなりません。同じツールを使えば誰でも正しいチェックサムを再生成できるからです。真正性は、次の組み合わせで担保してください。

  • 確認書への自署・押印（原本の保管）
  • 提出日時・職員番号・ツール版の記録（各レコードに埋め込み済み）
  • 提出ファイルの保存場所をアクセス権で統制する
  • 受領記録（誰からいつ受け取ったか）を残す

チェックサムの価値は、共有フォルダ経由でファイルが壊れた、転送中に文字化けした、後から誰かが数値を書き換えた、といった偶発的な問題に気づける点にあります。

4. 検証手順（回帰テスト）

信頼性は主張ではなく、テストで示します。前年分の紙の申告書が手元にあるなら、それが最高の正解データになります。

  1. 前年分の紙の申告書から、無作為に20件を選びます（部署・年齢・扶養の有無が偏らないように）。
  2. その20件を、このツールで入力します。
  3. 出力したCSVと、紙の申告書の記載内容を、項目ごとに突き合わせます。
  4. 一致しなかった項目について、原因を分類します（欄が足りない／選択肢が合わない／転記ミス／様式の理解違い）。
  5. 修正後、もう一度同じ20件で突き合わせます。

合格基準の例

  • 必須項目の一致率：100%
  • 金額項目の一致率：100%
  • 選択項目（続柄・同居区分など）の一致率：100%

一致率100%に達するまで本番運用しないでください。ここで残った不一致は、本番では必ず人事の手作業として跳ね返ってきます。

並行運用

回帰テストの次は、1部署だけを選んで、紙とツールの二本立てで1年運用します。

  • 紙の申告書は従来どおり提出してもらう（これが原本）。
  • 同時にツールにも入力してもらい、両者を突き合わせます。
  • 突合の結果を記録として残します。

この1年分の突合記録が、翌年からツール本番に切り替えるための、いちばん強い証拠になります。「試作をいきなり本番」ではなく「1部署で1年並行」が、信頼性に関する議論を終わらせます。

5. 税務上の位置づけについて、確認すべき質問リスト

以下は、所轄税務署または顧問税理士、組織内の税務担当に確認してください。回答を文書で残すことを強く勧めます。

  1. 年末調整の控除申告書について、従業員から勤務先への提供を電磁的方法で行う場合、書面の自署押印は必要ですか。
  2. 電磁的方法で提供する場合、データの形式や作成方法に要件はありますか（国税庁の年調ソフトによる作成が前提とされていますか）。
  3. 独自の様式（Webフォーム）で収集したデータを、人事が内容を確認したうえで法定の様式に確定する運用は、税務上問題がありますか。
  4. 控除証明書等の原本または写しの保管は、電子データで代替できますか。できない場合、何を保管すべきですか。
  5. 給与システムがCSV取込に対応している場合、その取込データを申告書の原本として扱えますか。
  6. 税務調査の際に、電磁的記録の提出を求められた場合、どのような形で提示すればよいですか。
  7. 令和8年分の様式変更（基礎控除の特例加算、扶養控除等申告書の「源泉控除対象親族」への改正、保険料控除申告書の「年齢23歳未満の扶養親族の有無」欄の追加など）について、追加対応が必要な点はありますか。

6. 可用性（属人化を避ける）

  • 変更内容・変更者・日付・理由を記録してください。
  • 年度更新の手順（TOOL_VERSION と FORM_YEAR の更新、様式との突合、回帰テスト）を毎年同じ手順で回してください。
  • 担当者は1人にしないでください。最低2人が、ファイルの場所・年度更新手順・テストの回し方を知っている状態にします。これは災害時の事業継続の観点でも説明できます。
  • 国税庁の年調ソフトは毎年10月頃に新しい年版が公開されます。様式の確定版もあわせて確認し、年度当初に差分を洗い出してください。

7. 機密性

  • このツールはサーバーを持たないため、アクセスログが取れません。これは弱点です。
  • したがって、保存場所と保存期間を決め、共有フォルダのアクセス権で統制してください。
  • 私物端末で入力する運用（BYOD）にする場合は、情報管理担当の事前合意が必須です。私物端末は利用場所・アプリ・アクセス先の統制が効かないため、リスクが上がります。
  • 提出が済んだファイルは、決めた保存期間を過ぎたら確実に削除してください。
